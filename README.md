# 被代办人记在哪里：家庭服务时间账

这里保存被代办人记在哪里：家庭服务时间账工作所用的匿名合成记录，以及按角色
拆分的负担分析。文件不包含居民个人资料。

## 资料

`samples/` 中每个文件都是独立的 UTF-8 JSON 文档：`frame`、`diary`、`events`、
`options`、`transport`、`policy`。日期是当地日历日期。空值表示没有对应观测或
状态资料，不是数值零。

日志时间为当地分钟；超出 1439 代表次日。行程号可跨家庭共用，个人身份为户号内
角色。`frame.weight` 为抽样扩权数，受保护标记由调查事先约定。集中办理的同办
许可、代办资格和供居民使用的车次独立于主观日记。`transport` 的 outbound 和
return 均按发车、到达排列；可到场时段、需陪同的家庭以及业务办理时长由调查和
排班资料给出。

## 运行

使用 Python 3.11，无第三方依赖。

```bash
python3 inspect_samples.py                     # 盘点原始资料条目数
python3 -m unittest discover -s tests -v       # 结构与行为测试
python3 -m service_time.report                 # 生成会议材料（Markdown）
python3 -m service_time.report --md out.md --json out.json
```

## 分析口径

`service_time/` 把同一份日记拆成角色时间，并在两种安排下重排合法行程：

| 模块 | 回答的问题 |
| --- | --- |
| `data` | 资料之间引用是否自洽（角色、行程、时间窗、片区车次） |
| `burden` | 日记里当事人、代办人、陪同者各自被记到多久；缺失返程给上下界，不当零 |
| `allocation` | 同车/公共行程如何分摊；家庭合计不随分摊口径变化 |
| `itinerary` | 两种安排下的合法替代行程：时间窗、办理时长、委托资格、同办许可、车次 |
| `compare` | 加权总体、角色、受保护组、未完成量、可比户与敏感性情景 |
| `calendar` | 跨日与整次行程的日历视图；缺前后锚点的区间标注为不可定界 |
| `evidence` | 资料能证明什么：哪些事项有办件事件、`complete` 指什么、可到场时段冲突 |
| `response` | 未答复、晚回执、假设台账与“建议依赖哪些不可确认假设” |
| `report` | 汇总为可复核的会议材料 |

几条硬口径：

- **分角色，再谈总量**。当事人只报“在点等候”，代办人报“乘车＋办件＋返程”，
  两者不能相加当作家庭总负担；只看一方会误判负担落给谁。
- **替代行程必须合法**。委托失效时，事项改由当事人到场、陪同者重排；不给原行程
  加常数，也不删除办不完的家庭；未完成事项计入未完成权重。
- **缺失不当零**。返程结束缺失按 `policy.missing_minutes_bounds` 给出区间。
- **权重只用于总体**。家庭权重用于总体估计，不再乘给实际每人当作独立样本。
- **口径要能追责**。报告列出抽样框、未答复家庭、晚回执、分摊不变性、敏感性情景
  与假设台账；会议可逐条核对哪些结论依赖无法确认的假设。
